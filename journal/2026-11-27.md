# 2026-11-27: the factory builds the daily retail ETL, 5 of 5

## Question

Given a written spec of the cleaning rules, can the factory build a daily ETL for Online Retail II
(workbook in S3 → parquet → `chaos_lab` Postgres, plus Lambda, schedule and alarms in Terraform)
that matches the reference row for row, and does it do so every time?

## Setup

- Ten identical issues, #15–#24, "ETL eval: Online Retail II daily ETL, trial k of 10". Run one at a
  time on the factory box (one chaos-lab write slot). Capped at five: #20–#24 were closed unrun.
- The spec spelled out the reference's rules in words: sheet overlap, duplicates, test and bad-debt
  rows, stock adjustments, free items, non-merchandise stock codes, sale/cancellation, and voids
  matched most recent lot first within 240 minutes.
- Each trial wrote only to its own namespace: `online-retail-ii/trials/issue-<N>/` in the lab bucket,
  schema `trial_issue_<N>`, `infra/trial-<N>/`. Terraform was applied to the session's moto emulator,
  never to real AWS.
- Grading after the run: each trial's parquet compared with the gold
  (chaos-lab-grader `gold/compare.py --target analysis`, 1,018,816 rows).

## Result

| Trial | PR | Outcome | F1 vs gold |
|---|---|---|---|
| #15 | #25 | success | 1.0 |
| #16 | #26 | success | 1.0 |
| #17 | #27 | success | 1.0 |
| #18 | #28 | success | 1.0 |
| #19 | #29 | success | 1.0 |

- **pass^5 = 5/5.** Every parquet matched the gold exactly: 1,018,816 rows, nothing missing, nothing
  extra. Every `trial_issue_N.transactions` held 1,018,816 rows.
- Cost $0.86–$1.32 per trial, **$5.29 total**. About 16–22 minutes and 1–2 factory reviews each.
- No writes outside each trial's namespace in S3 or the database.
- All five used IAM token auth with `rds-db:connect`, which fixed the gap in the first trial (#13 →
  #14), where the Lambda passed a password that a real deploy would have rejected and the reviewer
  missed it.
- No diff mentions the public reference repository the gold was built from. Session web searches were
  not inspected.
- The PRs were closed unmerged: these were eval runs.

## Takeaway

With the rules spelled out, this task is saturated: it no longer separates good runs from bad ones.
Harder evals need a looser spec or a broken pipeline to repair. Next: the reference ETL moves into
this repo (`pipelines/retail_etl/`), is deployed live, and the host breaks it. A bug-finder agent does
the RCA from the alarm and files an issue, and the factory fixes the code. Infra fixes are deployed by
hand.

## Loose ends

- Trial #14's parquet was left at `online-retail-ii/clean/`. That prefix is now empty; the live ETL
  writes there once this move is applied.
